# Soporte / Support

## Preguntas de uso y datos

Para dudas reproducibles sobre instalación, CLI, esquema, datos publicados o procedencia, abre un issue público usando la plantilla más cercana al problema. Incluye el tag de dataset (`data-YYYY.MM.DD`), versión del paquete, comando mínimo y salida relevante cuando aplique.

For reproducible questions about installation, CLI behavior, schema, published data, or provenance, open a public issue with the closest available template. Include the dataset tag (`data-YYYY.MM.DD`), package version, minimal command, and relevant output when applicable.

## Bugs y solicitudes de mejora

Usa **Issues** para errores no sensibles y **feature requests** para propuestas acotadas. Antes de abrir uno, revisa si ya existe un reporte equivalente.

Use **Issues** for non-sensitive bugs and **feature requests** for scoped proposals. Check for an existing equivalent report first.

## Seguridad

No publiques vulnerabilidades, credenciales, tokens, datos personales o rutas privadas en Issues. Sigue [`SECURITY.md`](SECURITY.md) y usa **Security → Advisories → Report a vulnerability**.

Do not post vulnerabilities, credentials, tokens, personal data, or private paths in Issues. Follow [`SECURITY.md`](SECURITY.md) and use **Security → Advisories → Report a vulnerability**.

## Datos arancelarios y cuestiones jurídicas

`arancel-mx` conserva procedencia y evidencia técnica, pero no sustituye las publicaciones oficiales ni constituye asesoría legal. Si reportas una posible discrepancia jurídica o arancelaria, incluye la fuente oficial, URL, fecha/publicación aplicable y el registro afectado.

`arancel-mx` preserves provenance and technical evidence, but it does not replace official publications and is not legal advice. When reporting a possible legal or tariff discrepancy, include the official source, URL, applicable publication/date, and affected record.
