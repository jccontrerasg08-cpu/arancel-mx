- **Estado:** propuesta | aceptada | reemplazada | descartada
- **Fecha:** AAAA-MM-DD
- **Responsable:** @usuario
- **Revisión:** @usuario o enlace a revisión
- **Enlaces:** issue, discusión y pull request cuando existan

## Contexto

Describe el problema verificable, el alcance afectado y por qué requiere una decisión transversal. No uses este formato para correcciones locales, cambios editoriales o mantenimiento rutinario.

## Decisión

Explica la opción aceptada, la frontera propietaria y el criterio observable que confirma su resultado.

## Alternativas

Registra las opciones consideradas y por qué no se eligieron. Incluye reutilización del repositorio, biblioteca estándar o dependencia existente antes de una solución nueva.

## Compatibilidad

Indica el impacto sobre API, esquema, release, datos, automatización o usuario. Para una ruptura, documenta reemplazo, versión objetivo, periodo de advertencia o la excepción justificada.

## Consecuencias y seguimiento

Enumera sólo las tareas de implementación, pruebas, documentación o retirada que sean consecuencia directa de la decisión.
